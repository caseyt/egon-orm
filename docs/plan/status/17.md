## What shipped

- **`@egon-orm/sqlite`** (`packages/sqlite`, now public): `sqlite({ filename, pragmas,
  readonly, planCacheSize })` over `better-sqlite3`.
  - `driver.ts`: a pool of one handle, handed to one caller at a time in FIFO order (two
    transactions never interleave); safe integers, given back as numbers where they fit;
    a prepared-statement cache of 500; cursors over `Statement.iterate`, closed on release;
    `destroy` of the connection rolls back an open transaction instead of closing the only
    handle; untyped booleans and `Date`s bound as SQLite stores them (`1`/`0`, timestamp
    text); `checkRuntime` turns better-sqlite3 13's crash on Node-API < 10 into an error.
  - `options.ts` (checked, pragmas validated as plain names and words, foreign keys on by
    default), `values.ts` (driver codecs, the table in the module doc), `errors.ts`
    (`normalizeSqliteError`: extended result codes, `<table>_<cols>_key` / `<table>_pkey`
    rebuilt from the columns, `SQLITE_BUSY`/`LOCKED` retryable), `dialect.ts`.
- **`@egon-orm/mysql`** (`packages/mysql`, now public): `mysql({ connectionString, host,
  port, user, password, database, ssl, pool, planCacheSize })` over `mysql2`.
  - `driver.ts`: prepared statements when there are values, text protocol otherwise;
    `-FOUND_ROWS`, with an `UPDATE`'s count read from "Rows matched"; the transaction
    state from the server status flag; streaming with the socket paused per batch;
    `KILL QUERY` (bound) on a connection of its own for cancellation; the pool wait bounded
    by `connectionTimeoutMs`; every session `time_zone = '+00:00'`.
  - `options.ts` (fixed settings: `dateStrings`, `supportBigNumbers`, `timezone: "Z"`,
    utf8mb4 `UTF8MB4_0900_AI_CI`, no multiple statements), `values.ts`, `errors.ts`
    (`normalizeMysqlError`: key names from `ER_DUP_ENTRY`, `PRIMARY` as `<table>_pkey`,
    deadlock / lock wait / timeout / connection codes), `dialect.ts`.

## Decisions

1. **Arrays are stored as JSON** on SQLite and MySQL (`DriverCodecs.array`), read back as
   arrays; array operators and `in(arrayExpression)` are refused (`arrays: false`).
2. **SQLite has one handle.** The pool is that handle; callers queue for it. A connection
   released with `destroy` (left in a transaction) has its transaction rolled back instead
   of the handle being closed.
3. **MySQL connections use `-FOUND_ROWS`** (affected rows = rows changed, so an upsert that
   changed nothing reports 0); an `UPDATE`'s row count is read from "Rows matched", the
   count the other databases report.
4. **MySQL upserts take no target** (`conflictTarget: false`): a `target` throws
   `QueryError` rather than being ignored. This departs from "upserts name their conflict
   target", which MySQL cannot do; see the owner table.
5. **SQLite row locks are accepted and not written** (`lockModes: []`), as the spec says.
6. **MySQL migration `text` is `varchar(255)`** (MySQL `TEXT` takes no index or default).
7. **New `SqlDialect` entry `sourceColumnList`**: SQLite takes no column list after a
   source's alias; a fragment source with columns is refused there. Only the repo builds
   fragment sources (`unnest`, Postgres only), so nothing public is lost.
8. **Begin refusals name the dialect** (`… is not supported by sqlite.`) instead of "this
   database"; `beginSql` gained an optional `dialect` parameter (default `"postgres"`).
9. Untyped `Date` parameters on SQLite bind as `timestamptz` text (as an untyped boolean
   binds as `1`/`0`).

## Deviations from the spec

- Three matrix cases changed their fragments so that every database can run them: "a CTE
  with a fragment body" and "a fragment as a source" no longer use `generate_series`, and
  "a table hint" takes a hint per dialect (`tablesample` / `use index` / `indexed by`).
  Their Postgres SQL changed accordingly.
- `sqlite({ filename: ":memory:" })` is not a second target for core's own integration
  tests: the SQLite suites already run without a service.
- The CI jobs existed (step 01); this step documents what each runs.
