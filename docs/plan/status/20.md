# Step 20: Documentation, status

Branch `step/20-documentation`, 2026-10-20. Spec: `docs/plan/20-documentation.md`. Built
after steps 01 to 18 merged; step 19 (performance) is postponed, so the site has no
performance page and no numbers (where a page needs one, it says "measured in step 19").

## What shipped

### Part A: tooling (what was still missing after step 01)

Step 01 had set up VitePress with local search, dark mode, a `DOCS_BASE` base path, and
`docs/site/examples` type-checked by `pnpm typecheck`. Added:

- **Runnable examples.** A file under `docs/site/examples/` whose first lines hold
  `// @run` runs in `pnpm test:integration` (new Vitest project `docs:integration`,
  `docs/site/test/examples.itest.ts`) against a database of its own. A Vite plugin in
  `vitest.config.ts` turns each `statement; // => value` line into a deep-equality check,
  keeping line numbers; a runnable example that checks nothing fails. 16 examples run:
  getting started, the shared "Coming from" example and 13 recipes. Mutation-checked: a
  wrong `// =>` value fails with the file and line.
- **API reference.** TypeDoc 0.28 with `typedoc-plugin-markdown` and
  `typedoc-vitepress-theme`, generated into `docs/site/api/reference/` (git-ignored) by
  `pnpm docs:api`, which `docs:build` and `docs:dev` run first. A local plugin
  (`docs/site/typedoc-plugin.mjs`) names the modules by import specifier and **fails the
  build on an export without an `@example`**; TypeDoc's `notDocumented` validation with
  `treatWarningsAsErrors` fails it on one without a summary. It found one gap,
  `PragmaValue` in `@egon-orm/sqlite`, which now has an example (Deviations).
- **Docs lint**, `pnpm docs:check`, part of `pnpm lint` (`scripts/check-docs.mjs`, unit
  tests in `scripts/check-docs.test.mjs`):
  1. no hand-written `ts`/`js`/`tsx` block (`<!-- illustrative -->` allows deliberately
     invalid code; none uses it today);
  2. every snippet include names an existing file and region;
  3. `// =>` only in `// @run` files;
  4. none of the positioning that plan README §8 rules out, in pages, examples, README, CONTRIBUTING or anything under
     `packages/`;
  5. every export of the eight entry points is in the index of exports, and every value
     export (function, class, constant) is also named on a written page or shown in an
     included example;
  6. every page is in the sidebar and every sidebar link is a page;
  7. the README example equals the `example` region of `docs/site/examples/home.ts`.
- **Index of exports**, `reference/exports.md`, generated by `scripts/api-index.ts` (TypeScript
  compiler API: every export, its kind, the first sentence of its TSDoc, a link to its API
  page), grouped by entry point and, for `egon-orm`, by topic. `pnpm lint` fails when it is
  stale.
- **Anchor check**, `scripts/check-anchors.mjs` (with a test), run at the end of
  `docs:build`: VitePress fails on a link to a missing page but not to a missing
  `#heading`. Mutation-checked. It found nothing broken at the end, but the build itself
  caught 13 dead links in the first index (classes exported as types).
- **Spell checker**, cspell 10.3.6 with `en,en-GB` and a project word list
  (`docs/site/words.txt`, five words), over the site, README and CONTRIBUTING; inline code,
  fences and URLs are skipped. Probed with a deliberate typo.
- **Edit links** on every page; the local search index leaves out the generated API pages
  (with them it was 2.7 MB and Vite warned about the chunk size; it is now 0.4 MB, and the
  build has no warnings).
- **Deployment.** CI's `docs:build` job now uploads the built site as the `docs-site`
  artifact (7 days) on every PR; `.github/workflows/docs.yml` builds `main` with
  `DOCS_BASE=/<repository>/` and deploys to GitHub Pages. Actions pinned by SHA like the
  others.
- **Page template** and the docs tooling written up in `CONTRIBUTING.md` (new
  "Documentation" section).

## Deviations and decisions

1. **Paths outside the step's own**, each needed by the tooling:
   - `vitest.config.ts`: the `blog:integration` and `docs:integration` projects and the
     `// @run` transform.
   - `tsconfig.json`: a reference to `examples/blog`.
   - `package.json`: `docs:api`, `docs:exports`, `docs:check` (added to `lint`), cspell.
   - `.gitignore`: the generated API reference.
   - `.github/workflows/ci.yml`: the preview artifact; new `.github/workflows/docs.yml`.
   - `packages/sqlite/src/options.ts`: an `@example` on `PragmaValue` (TSDoc only).
   - `pnpm-lock.yaml`: TypeDoc and its two plugins, cspell, Express, Fastify, Hono,
     `@types/express`, `@types/react`, vitest and tsx for the docs and the blog. No
     `minimumReleaseAgeExclude`; strict mode on; `pnpm lint`'s policy check passes.
2. **The API reference is grouped by package, then by kind**, not by the module list of the
   spec (Schema, Types, Changeset, …): TypeDoc groups by entry point, and grouping by
   feature would need `@category` tags in every package's sources. The topic grouping is in
   `api/index.md` and in the index of exports instead.
3. **"Referenced from a guide"** is checked as: listed in the generated index (every
   export), and, for values, named or shown on a written page. 240-odd exported types
   appear only in the index and the API reference.
4. **A bare `x;` is not a use to Biome** (`noUnusedVariables`), so runnable examples check
   a property or a comparison (`rows[0]; // => …`, `seen === 45; // => true`) where the
   statement would otherwise be a lone variable. No rule was turned off.
5. Tutorial and getting started use **migrations** (step 18 shipped), not SQL fixtures.
   The tutorial runs its migration script with tsx: Node's own type stripping does not
   map the `.js` imports between the app's files to `.ts`.
6. The VitePress DocSearch component (unused: search is local) declares a peer dependency on
   React 18 types; `@types/react` 19 for the React recipe makes `pnpm install` print a peer
   warning. It fails nothing.
7. The positioning check has to contain the name it looks for: it is in one regular
   expression in `scripts/check-docs.mjs` and in the sample text of its unit test. Nothing
   users read contains it; the check does not scan `scripts/`.
