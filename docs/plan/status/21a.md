# Step 21a: Edge readiness, status

Branch `step/21a-edge-readiness`, 2026-10-21. Spec: `docs/plan/21a-edge-readiness.md`.
Decision record: [ADR 0007](../../adr/0007-error-identifiers-and-full-messages.md),
**accepted by the owner on 2026-10-21** (as proposed, then amended the same day to add
`explain(error, messages?)` beside `useFullErrorMessages(messages)`).

## What shipped

### 1. Code generation that survives a request-time refusal

- `packages/core/src/internal/codegen.ts`: `generateFunction(params, body)` is now the only
  place that calls `new Function`. It tries at the moment code is generated and remembers
  only a refusal (an `EvalError`); any other error (a bug in generated source) is thrown.
  The two module-load probes (`schema.ts`, `validators/validate.ts`) and the probe of
  `hydrate.ts` (`canGenerate` / `generationAllowed`, removed) are gone.
- **Eager in `Schema()`:** the schema's row constructor is generated as a *maker* (a
  generated function that returns a fresh constructor), so a class that extends the schema,
  whose metadata is made on first use (often during a request), gets its constructor
  without generating code. The two validator builders of the schema's field table are
  generated in `Schema()` too (`changeset/validators/generated.ts`, which imports nothing of
  the changeset code, so a schemas-only bundle does not grow).
- **Lazy with fallback:** factories with preloads (`createWith`), validator tables of
  schemaless changesets, and query decoders are generated on first use, or built from the
  existing loops where the runtime refuses.
- `meta.codegen` now means "generated functions were asked for" (the option); whether they
  were made shows in `meta.maker`. `codegen: false` on a schema or repo still never calls
  `new Function`.
- Tests: `internal/codegen.test.ts` runs the same work twice in fresh module graphs, once
  normally and once on a fake runtime whose `Function` succeeds during "startup" and throws
  `EvalError` afterwards, and compares the results (rows, key order, prototypes, validator
  values, decoded rows); a second test checks that what `Schema()` generated is used after
  the refusal with no new attempt. The two tests that pinned probe-once behaviour
  (`hydrate.test.ts`, `schema.test.ts`) now pin attempt-on-use and remember-refusal.
- **Cost (not measured; step 19):** each `Schema()` call now compiles three functions (the
  row-constructor maker, as before one per schema, plus the two validator builders, which
  were compiled on the first `validate()` of the schema before). A schema that is never
  validated pays for two compilations it did not pay before, once, at startup. Each
  subclass's constructor is now a closure made by the maker instead of a fresh compilation,
  which is cheaper. Nothing changed per row or on a plan-cache hit.

### 2. A plan cache shared across adapters

- `adapter/compiler.ts` `sharedStatementCompiler`: adapters created with the same dialect,
  capabilities object, driver-codecs object and `planCacheSize` share one compiler, plan
  cache and `typeOverrides` (a module-level map: dialect → `WeakMap` by capabilities →
  `WeakMap` by codecs → `Map` by size). The dialect packages pass module-level constants,
  so a repo made per request reuses earlier plans. Each definition is still checked against
  the dialect's SQL table.
- **`planCacheSize` keeps its contract** (README §11): it is still an adapter option and the
  bound of the cache that adapter uses; adapters with different sizes do not share. No
  change needed the owner's decision. One observable difference: `planCacheStats()`
  counts the shared cache, so it includes lookups of other adapters of the same
  configuration (documented on `DatabaseAdapter.planCacheStats` and `planCacheSize`). The
  read-conformance test of the counters now allows a shape compiled by an earlier test.
- Tests (`adapter.test.ts`): two adapters with the same configuration share plans (the
  second compiles nothing, `typeOverrides` is the same function); other codecs, other
  capabilities or another size do not share; 40 per-request adapters with 40 shapes keep the
  cache at `planCacheSize: 8`; a shared compiler still refuses a definition whose
  `quoteIdentifier` disagrees. The Worker check (part 6) shows reuse across requests.

### 3. A build that tree-shakes and keeps `node:` imports

- Every package is built **unbundled** (`bundle: false`, one file per source module, tests
  and fixtures left out), with `removeNodeProtocol: false`. Public entries:
  `dist/index.js`, `dist/migration/index.js`, `dist/testing.js`, the new
  `dist/messages/index.js`; declarations stay bundled per entry. `dist/internal/index.js`
  (the benchmark barrel) is still excluded from the published files; the rest of
  `dist/internal/` is published (the public modules import it). The three benchmark files
  that load the built internal barrel now load `dist/internal/index.js`.
- `/* @__PURE__ */` on every call and `new` evaluated when a published module loads, kept by
  `scripts/check-pure-annotations.mjs` (in `pnpm lint`, with `--fix`; unit tests in
  `scripts/check-pure-annotations.test.mjs`). It also refuses a spread inside such a call
  (the option-key tables and two dialect tables were rewritten with `concat` /
  `Object.assign`), a chained call one annotation cannot cover, a tagged template and a
  top-level statement that runs something (the `egon` executable is exempt).
- `scripts/check-node-specifiers.mjs` (with tests) fails on a built-in imported without
  `node:` in any dist; CI's build job runs it after `pnpm build`. Before this step
  `@egon-orm/postgres` imported `net` and `tls`.
- `scripts/size-report.mjs` packs `egon-orm` and `@egon-orm/postgres`, installs the tarballs
  in a temporary directory and bundles the reference app and subset imports with esbuild
  (minified, ESM, `pg` external). It reports, never fails. `node scripts/size-report.mjs
  <checkout>` measures another checkout's built packages.

### 4. Error identifiers, short messages, full text by opt-in

- Every thrown message has an identifier, `error.id`: **639** of them, typed as the union
  `ErrorId`, namespaced by class (`query.aliasTaken`, `schema.noPrimaryKey`,
  `database.timeout`, `migration.missingSteps`; a class with one message uses its code:
  `noResults`, `multipleResults`, `invalidChangeset`, `staleEntry`, `notLoaded`).
- The default message is `<id>: <short sentence> See <link>`. The short sentence keeps the
  values the message interpolated before (clause, schema, field, SQL state, counts); the
  advice moved to the catalog `packages/core/src/messages/catalog.ts`, entry
  `egon-orm/messages`. Where splitting dropped a value of what was given ("it returned
  null"), the value was put back into the short sentence (audited for every site).
- **Opt-in (ADR 0007):** `useFullErrorMessages(messages)` from `egon-orm` (a catalog or
  `null`; a custom or translated catalog works, missing entries keep the short message) and
  `explain(error, messages?)` from `egon-orm/messages`, stateless, for any value (non-Egon
  errors give `name: message`, other values `String(value)`, unknown identifiers or another
  copy's errors give the message as it is). The catalog's `{{name}}` placeholders are filled
  from the error's parameters.
- `error.toJSON()` returns `{ name, code, id }` for every class (tested for each), so
  `JSON.stringify(error)` leaves out the message, cause and SQL.
- Constructors: `QueryError`, `CastError`, `SchemaDefinitionError`, `DatabaseError` and
  `MigrationError` take `(id, message, details?)`; `details` carries `params` and `cause`
  (and, as before, `code`/`retryable`/`sql`, `version`/`migration`/`sql`). `ConstraintError`
  and `RollbackError` take optional `id`/`message`/`params`. The identifier must belong to
  the class's namespace (type-checked). See Needs the owner's decision.
- Internal helpers in `errors.ts` (not exported from `index.ts`): `shortMessageOf`,
  `rewrap` (adds context, such as `where(): `, keeping the identifier and parameters),
  `fullMessageOf`, `docsLink`, `IdsOf`.
- **Docs:** `pnpm docs:errors` (`scripts/error-docs.ts`) generates one page per namespace
  under `reference/errors/` with every identifier, its short message as the source writes
  it and its advice. `pnpm docs:check` runs it with `--check`: it fails when a page is
  stale, an identifier is thrown without a catalog entry, an entry is thrown nowhere, an
  entry has no advice, or a site does not pass a `{{name}}` its entry uses
  (mutation-checked). `reference/errors.md` explains identifiers, both opt-ins, the
  import-time limitation and `toJSON`.
- **Tests:** unit and integration tests run with full messages (a setup file,
  `packages/core/test/support/full-messages.ts`, in `vitest.config.ts`), so tests that
  matched advice still can; tests that compared whole messages now compare the identifier
  and short sentence or the full text (`messageText` in test-support), and anchored regexes
  allow the identifier prefix. `errors.test.ts` and `messages/index.test.ts` turn full
  messages off and test the default form, the opt-in, a custom catalog, `explain` (including
  an error thrown while a module was imported, before any opt-in), `toJSON` and `rewrap`.

### 5. `@egon-orm/postgres` on the edge

- `cancel.ts` imports `node:net` and `node:tls` on the first cancel request, once, and
  rejects with an explanation where they are missing (the adapter then lets the statement
  finish and drops the connection, as for any failed cancel). Tested by mocking the modules
  (`cancel-load.test.ts`, mutation-checked: a static import fails it).
- The per-request pattern (`ctx.waitUntil(repo.close())`) is in `guide/edge.md`.

### 6. A Workers check in CI

- `examples/edge-worker/`: the reference app as a Worker (`nodejs_compat`), built with
  `wrangler deploy --dry-run --minify` (wrangler 4.149.0) and run by `run.mjs` in workerd
  through Miniflare 4.20260730.0 against a database of its own on the test Postgres. It
  checks ten things: an insert; a select with where/orderBy/limit; that **workerd refuses
  code generation during the request**; that the rows are instances of the schema class
  anyway (interpreted decoder); a second request running the query again with a new repo
  and **reusing the first request's plan**; the default message (identifier, sentence,
  link, no advice); `explain`; `JSON.stringify(error)`; and the message after
  `useFullErrorMessages`. Telemetry off (`send_metrics = false`, `WRANGLER_SEND_METRICS`),
  no login, no deploy.
- CI job `edge worker` runs it and writes the Worker's size and the size report to the job
  summary; `ci` requires it.

### 7. Docs

- `guide/edge.md` (new; in the sidebar): Workers with `nodejs_compat`, a repo per request,

imports gain a lot (from the unbundled build). See Needs the owner's decision.

## Decisions

- Identifier format and message format as ADR 0007 (A1, B); anchors are the identifier with
  `.` as `-`, lowercased; pages per namespace, `general` for the class-coded ones.
- `ErrorId` is derived from the catalog's keys (`keyof typeof messages`, a type-only
  import), so the catalog cannot lack an identifier a site uses and a site cannot use one
  that is not in it; the docs check covers the other direction and the parameters.
- `RollbackError` got three identifiers (`rollback.called`, `.statementFailed`,
  `.batchFailed`) and `ConstraintError` two (`constraint.violated`, `.undeclared`), since
  each already had several messages.
- `unsupported(dialect, feature)` keeps one identifier, `query.unsupportedFeature`, for its
  45 features (the message is one template; the feature is in the sentence).
- Internal invariant errors of the query tree (a malformed AST) got identifiers of their
  own (`query.ast*`) whose advice says the tree was built or changed by hand.
- `explain` takes the catalog as an optional parameter defaulting to the English one: it
  lives in `egon-orm/messages`, so the default costs nothing more (ADR 0007, amended).
- `egon-orm/messages` exports `explain` and `messages` only (the types are `egon-orm`'s;
  re-exporting them gave TypeDoc duplicate pages and dead links).

## Needs the owner's decision

1. **The size outcome.** The reference app saves 8 KB / 4.4 KB gzip, not the ~46 / 14 KB the
   research simulated, because ADR 0007 keeps a short sentence with values at every site
   (decided) and the identifiers are descriptive (decided). Options, if more is wanted:
   shorter sentences (an editorial pass; the values stay), numeric identifiers (≈10 KB less
   text, a change to the accepted ADR), or splitting the MySQL/SQLite SQL tables out of the
   Postgres path (the prototype's P2; not in this step's list).
2. **Constructors changed for third-party code.** `new DatabaseError(message, details)` is
   now `new DatabaseError(id, message, details)` (likewise `QueryError`, `CastError`,
   `SchemaDefinitionError`, `MigrationError`). A third-party adapter that builds these breaks
   at compile time (and at run time: a message string where an identifier is expected gives
   a wrong message). There is no identifier namespace for third-party messages; they would
   reuse ours (`database.rejected`, `database.connectionFailed`). Worth a line in
   `reference/upgrading.md` at release (step 21).
3. **The CLI prints short messages now.** `egon migrate` and friends print
   `<id>: <sentence> See <link>`, without the advice they printed before (for example
   "A migration has both up(m) and down(m)…"). One line in `packages/cli/src/bin.ts`
   (`useFullErrorMessages(messages)`), not in this step's paths, would restore it for the
   CLI; see Requests.

## Requests

- **CLI** (`packages/cli/src/bin.ts`, `cli.ts`): call `useFullErrorMessages(messages)` when
  the `egon` executable starts, or print `explain(error)`; the CLI is a development tool and
  its size does not matter. `packages/cli/test/cli.itest.ts` would then match the full text
  again.
- **Step 19:** the benchmark comments about `dist/internal.js` (separate classes) are
  outdated; with the unbundled build `dist/internal/index.js` shares every class with
  `dist/index.js`, so the benchmarks may import from either.
- **Step 21:** the upgrading/changelog entries for the error format, `error.id`,
  `egon-orm/messages`, the constructor change and the shared plan cache.
- **Step 21b:** this branch touches `schema/schema.ts` (row-constructor maker, eager
  validator builders) and every error site; rebase notes: the error constructors take an
  identifier first.

## Not verified

- **Benchmarks and budgets:** deferred to step 19 (owner decision, 2026-10-14). Nothing was
  measured for speed; the cost of eager generation is reasoned above.
- Hyperdrive, a real Cloudflare deployment and Vercel Edge were not tried; the guide's
  Hyperdrive section rests on Cloudflare's documentation. The research's observation that a
  reused repo hangs on later requests was not reproduced here.
- Cancellation on Workers (a `timeoutMs` that fires there) was not run; the lazy load is
  tested in Node with mocked modules.
- The Worker check runs on Miniflare 4.20260730.0 (workerd 2026-07-30, compatibility date
  2026-07-01), not the Miniflare 5 alpha that wrangler 4.149.0 depends on, whose options
  changed shape.
- A browser with a Content Security Policy was not tried; the fallback is the same code
  path as in workerd.
- `useFullErrorMessages` with two copies of `egon-orm` loaded: each copy has its own
  setting (stated in the ADR, not tested).
